AInstalar na máquina do plantãoDispatcher N1 · uns 15 minutos
  1. Copiar o instalador dist\instalador\DispatchBot-Setup-1.7.0.exe para a máquina e rodar. Não pede administrador. Deixe marcado “Iniciar com o Windows”.
  2. Login no ServiceNow na janela que o robô abre: ele clica em “Use external login” sozinho; o plantonista faz o resto (e-mail, conta Microsoft, Windows Hello).
  3. Login Microsoft no navegador do robô, se a janela do SharePoint aparecer pedindo. Depois disso a fila é lida sem abrir janela.
  4. Conferir o ícone na bandeja: verde é ativo. Vermelho mostra o motivo ao passar o mouse.
  5. Deixar as outras máquinas em Pausado pelo menu do ícone. Só o Dispatcher N1 da vez fica ativo.

Log em %LOCALAPPDATA%\DispatchBot\logs\robo.log. É nele que aparecem os avisos de login e as renovações de sessão.

BConferir o formulário de Backup no portal realConcluído em 05/10/2026 · Failure Type entra como Execution failure (1.6.2)
  1. Rodar o teste no Prompt de Comando da máquina instalada: 
    "%LOCALAPPDATA%\Programs\DispatchBot\DispatchBot-Mapear.exe" --testar "%LOCALAPPDATA%\Programs\DispatchBot\exemplos\BACKUP.json"
  2. Olhar a tela preenchida: título #FALHA DE BACKUP …, serviço afetado Veritas Netbackup e o texto do impacto na língua do portal.
  3. Ler a lista de obrigatórios que o teste imprime. Se “Failure Type” aparecer como VAZIO, ele precisa entrar no config.
  4. Fechar sem enviar. Se algo não bateu, mande a saída do teste para ajustar o config.default.json.

Não clique em Enviar. O teste nunca envia sozinho, mas a janela fica aberta com o formulário pronto.

CTrocar o título do BackupPower Automate · BackupBot
  1. Abrir uma execução antiga do BackupBot e copiar uma linha de falha (o item() do loop “Para Cada Falha”).
  2. Confirmar as colunas, que foram deduzidas (o CSV não tem cabeçalho):
    ÍndiceColuna
    [0]JobID
    [2]Política
    [3]Cliente
  3. Trocar o titulo do JSON_BACKUP, no lugar de take(item(),80): 
    concat(split(item(), ',')[2], ' | ', split(item(), ',')[3], ' | Job ', split(item(), ',')[0])
    Resultado: #FALHA DE BACKUP YDUQS_VMWARE_X | servidor01 | Job 26509786
  4. Opcional: remover a ação “Run a flow built with Power Automate for desktop”. Era só teste e é o que deixa o fluxo premium.

Combinado: os fluxos existentes não são alterados. Se preferir, faça a troca numa cópia (Save As) e vire depois.

DCriar o fluxo DispatchBot | RetornoPower Automate · posta o número no chat do time

Um fluxo só para todos os tipos. Os chats são em grupo, sem thread: o fluxo posta uma mensagem nova citando a CHG ou a falha de Backup.

  1. Gatilho SharePoint · When a file is created (properties only): site MANAGEDSERVICE, biblioteca Documentos Compartilhados, pasta YDUQS/N1/DispatchBot-Fila/retorno. Em Settings → Trigger conditions: 
    @endsWith(triggerOutputs()?['body/{FilenameWithExtension}'], '.json')
  2. Get file content (mesmo site), File Identifier = Identifier do gatilho.
  3. Compose Retorno: 
    json(body('Get_file_content'))
    Se der erro de tipo, use json(base64ToString(body('Get_file_content')?['$content'])).
  4. Compose Mensagem: 
    if(equals(outputs('Retorno')?['status'], 'ok'),
   concat('✅ ', outputs('Retorno')?['tipo'], ' ', if(equals(outputs('Retorno')?['tipo'], 'BACKUP'), outputs('Retorno')?['titulo'], outputs('Retorno')?['id']), ': chamado ', outputs('Retorno')?['numero'], ' aberto. Tratar: ', outputs('Retorno')?['url']),
   concat('⚠️ ', outputs('Retorno')?['tipo'], ' ', if(equals(outputs('Retorno')?['tipo'], 'BACKUP'), outputs('Retorno')?['titulo'], outputs('Retorno')?['id']), ': o robô NÃO abriu o chamado. Abrir manualmente. Motivo: ', outputs('Retorno')?['mensagem']))
  5. Switch em outputs('Retorno')?['tipo'], um Case por chat, cada um com Teams · Post message in a chat or channel (Flow bot, Chat em grupo, mensagem = outputs('Mensagem')). Default vazio.
    CaseChat em grupo
    INFRA(FC) NET / SOC
    DBA(FC) BANCO DE DADOS (DBA'S + N1 + Gestão)
    SO(FC) LINUX - WINDOWS - VMWARE
    BACKUP(FC) NETBACKUP
  6. Opcional: SharePoint · Delete file com o mesmo Identifier, para a pasta retorno ficar limpa.
  7. Testar sem postar: grave em retorno um arquivo com tipo de teste. Ele cai no Default; confira no histórico da execução se a Mensagem saiu certa. 
    {"id":"CHG0000000","tipo":"TESTE","titulo":"teste","status":"ok","numero":"RITM0000000","mensagem":""}
EPiloto com BackupPrimeiro chamado real, com o plantonista conferindo
  1. Esperar uma falha real de Backup. O BackupBot grava o JSON em pendentes e o robô preenche o formulário.
  2. Plantonista confere e clica em Enviar. O ícone fica amarelo e aparece um aviso na tela. Sem clique em 30 min, o alerta vai para erro.
  3. Conferir o resultado: número INC no chat (FC) NETBACKUP e o arquivo em processados.
  4. Medir a sessão do ServiceNow durante o plantão: contar no log quantas vezes o robô pediu login. Isso mostra o tempo real de sessão da Cirion.
  5. Ver a renovação do SharePoint: quando a sessão Microsoft vencer, o robô renova sozinho ou abre a janela pedindo login.
FLigar a GMUDDepois do piloto de Backup
  1. Conferir o Default do Switch no GMUD | Todos: precisa ter Control → Terminate (Succeeded). Vazio, um alerta de PRODUCAO chega à fila e cai em erro com aviso.
  2. Acompanhar as primeiras GMUDs de INFRA, DBA e SO: plantonista confere o título #GMUD CHG… | SOC/DBA/SO | dd/MM HH:mm | e clica em Submit.
  3. Envio sem conferir (opcional, decisão do plantonista): menu do ícone → “Enviar GMUD sem conferir”.
