DispatchBot: alertas de GMUD viram chamados no ServiceNow

O fluxo GMUD | Todos (INFRA, DBA e SO) e o BackupBot continuam postando no Teams. Agora, cada alerta também abre um chamado no Employee Center da Cirion. Isso é feito por um robô local que usa a sessão SSO do Dispatcher N1 de plantão.

Visão geral

Caminho de um alerta

A API do ServiceNow não está disponível e o login é por SSO com MFA. Por isso, a abertura do chamado é automação de navegador na máquina do plantonista. O Power Automate e o robô se comunicam por arquivos JSON numa pasta do SharePoint, que o robô lê pela API REST.

1OutlookE-mail de alertaGatilho “When a new email arrives (V3)” no GMUD | Todos e no BackupBot.
2Power AutomatePost no Teams + JSONMantém o card do Flow bot e grava <TIPO>_<id>.json em /pendentes.
3Máquina do N1Robô localLê a fila no SharePoint (API REST, com a sessão Microsoft do navegador do robô), reserva o arquivo e preenche no Edge com o perfil próprio do robô.
4ServiceNow ESCChamado abertoPreenche o formulário do tipo, confere os obrigatórios e clica em enviar (se faltar algum, o plantonista completa e envia); o robô captura o número (RITM na GMUD, INC no Backup).
5Power AutomateMensagem no chat do timeO fluxo “DispatchBot | Retorno” lê /retorno e posta o número e o link de tratamento no chat em grupo do time.

Decisões

O que foi decidido

A

Empacotamento com PyInstaller (onedir)

O Python embeddable não traz o tkinter, que é usado no diálogo da primeira execução, e o pip nele é frágil. O PyInstaller empacota o driver do Playwright sem nenhum navegador. O modo onedir abre mais rápido e o antivírus corporativo reclama menos que no onefile.

Saída: DispatchBot.exe e DispatchBot-Mapear.exe, cerca de 150 MB (medido no build). O driver do Playwright ocupa cerca de 105 MB e nenhum navegador entra no pacote.

Fechada
B

Instalador por usuário, sem admin

O Inno Setup roda com PrivilegesRequired=lowest e instala em %LOCALAPPDATA%\Programs\DispatchBot. Cria um atalho no Menu Iniciar e tem a opção “Iniciar com o Windows” via HKCU\…\Run. Os dados ficam em %LOCALAPPDATA%\DispatchBot e sobrevivem a atualizações.

Fechada
C

Fila lida direto no SharePoint, por polling

O robô lista /pendentes pela API REST do SharePoint no intervalo do config (15 s), sem OneDrive. A autenticação usa os cookies da sessão Microsoft (FedAuth/rtFa) salvos no perfil do navegador do robô: na maioria das vezes ele nem abre o site. Quando a sessão vence, visita o site para renovar; se a Microsoft pedir login, abre uma janela e espera o plantonista. A pasta sincronizada pelo OneDrive ficou só como modo reserva (fila_sharepoint.site vazio).

Fechada
D

Um robô ativo por vez

A reserva move o arquivo de pendentes para processando com o MoveTo do SharePoint, que é atômico: duas máquinas nunca pegam o mesmo arquivo. Mesmo assim, só o Dispatcher N1 de plantão roda o robô ativo; nas demais máquinas, ele fica em Pausado.

Resposta: só o plantonista da vez (Dispatcher N1). A pesquisa no ServiceNow antes de abrir o chamado fica desligada por padrão, com um liga/desliga no config.
Fechada
E

Nunca abrir dois chamados para o mesmo alerta

O id do alerta é gravado como enviando antes do clique em Enviar e como ok junto com o número depois. Se o robô cair no meio, o alerta vai para /erro para conferência manual. O envio nunca é repetido às cegas.

Fechada
F

Navegador e login SSO

  • Usa o Edge (msedge) e, se ele não estiver instalado, o Chrome. O contexto é persistente, no perfil do robô, e nunca no perfil pessoal.
  • Quando o navegador cai na tela de SSO, o ícone da bandeja fica amarelo, aparece o aviso “Faça login no ServiceNow na janela aberta” e o robô espera o portal voltar.
  • O robô nunca guarda nem digita senha.
Fechada
G

Formulários descritos no config, um bloco por tipo

Para cada tipo, o config tem a URL do formulário, uma lista de passos (preencher, selecionar, referencia, clicar…), o botão de envio e a regex que captura o número. Adicionar um tipo novo é criar outro bloco. Um tipo desconhecido vai para /erro. O DispatchBot-Mapear.exe --testar preenche o formulário sem enviar e lista os campos obrigatórios que ficaram vazios.

Fechada
H

Número do chamado postado no chat do time

Um único fluxo novo, DispatchBot | Retorno, atende todos os tipos. Os alertas são postados em chats em grupo, que não têm thread: o Retorno posta uma mensagem nova no chat do time, citando a CHG (ou a falha de Backup) e o número. O chat sai do tipo do JSON, então os fluxos de alerta não precisam guardar o id da mensagem.

Chats: INFRA → (FC) NET / SOC · DBA → (FC) BANCO DE DADOS (DBA'S + N1 + Gestão) · SO → (FC) LINUX - WINDOWS - VMWARE · BACKUP → (FC) NETBACKUP.
Fechada
I

Onde fica a pasta /DispatchBot-Fila

Uma biblioteca de documentos do SharePoint do time: não depende da conta de uma pessoa e os fluxos usam o conector do SharePoint.

Criada em 01/10/2026: site MANAGEDSERVICE, biblioteca Documentos Compartilhados, pasta YDUQS/N1/DispatchBot-Fila. No config: fila_sharepoint.site e fila_sharepoint.pasta.
Fechada
J

Número da GMUD é o RITM, com link de tratamento

O formulário Hosting cria um caso CS e um RITM ligado a ele. O time trabalha com o RITM, então o robô lê só a linha do RITM e o cabeçalho do caso (a descrição pode citar outros chamados) e espera até 30 s pelo RITM antes de aceitar o CS. Junto com o número vai o link de tratamento: abre o chamado direto na tela clássica do ServiceNow (link_tratamento no config; a tabela sai do prefixo do número).

Confirmado em 05/10/2026: CS0720955 → REQ0415170 / RITM0415846. O link vai no retorno, no histórico e no painel.
Fechada
K

Painel do plantonista (tema escuro) e janela "Precisa de você"

Clicar no ícone da bandeja abre o painel em tema escuro (CustomTkinter, ícones do Windows): status com o detalhe, contadores do dia, Precisa de você (login, chamado para conferir, alerta antigo), chamados abertos hoje (Tratar abre o chamado na tela de tratamento; Copiar) e erros de hoje com o motivo. Rodapé: Verificar agora, Logs e PARAR AGORA. Quando o robô precisa do plantonista, uma janelinha aparece sozinha no canto da tela, mesmo com o painel fechado. O ícone é o avatar do robô com uma bolinha na cor do status.

Fechada
L

Fluxos agrupados numa Solução

No Power Automate, os fluxos ficam na Solução DispatchBot. O e-mail de Backup chega numa caixa diferente da GMUD, e cada fluxo tem um gatilho só; por isso não existe um fluxo de entrada único. São três: GMUD | Todos, BackupBot e DispatchBot | Retorno.

Decidido em 09/10/2026. O Retorno já nasceu na Solução; os outros dois entram por “Adicionar existente”, sem mexer na lógica.
Fechada
Segurança

Parada de emergência

Se o robô estiver abrindo chamados errados, qualquer pessoa para na hora. O robô interrompe no meio do passo, fecha o navegador e não volta sozinho. Um alerta que ainda não foi enviado volta intacto para a fila. Um alerta que já foi enviado vai para /erro para conferência e nunca é reenviado.

Resiliência

Quando algo dá errado

Cada situação abaixo foi testada contra um ServiceNow simulado e com o instalador na pasta real de instalação. O princípio é o mesmo em todas: repetir só o que é seguro repetir, e nunca reenviar um formulário que pode ter sido enviado.

SituaçãoO que o robô faz
Rede, instância lenta (503), navegador travadoTenta até 3 vezes com um navegador novo, depois manda para /erro
ServiceNow recusa o formulárioVai para /erro na hora com a mensagem da tela, sem repetir
Falha depois do clique em EnviarVai para /erro com “confira no ServiceNow” e nunca reenvia sozinho
SSO entra sozinhoSegue sem avisar ninguém
Ninguém faz o loginO alerta volta para a fila e espera. Depois de 60 min, vai para /erro e o Teams avisa para abrir manualmente
SharePoint fora do ar ou config.json com erroÍcone vermelho com o motivo. Volta sozinho quando o problema é resolvido
Sessão Microsoft vencida (SharePoint)Renova sozinho; se a Microsoft pedir login, abre a janela e o ícone fica amarelo
Sessão do ServiceNow paradaCom o navegador ocioso, o robô recarrega o portal a cada 10 min. Se a sessão caiu, pede o login na hora, e não no próximo alerta
Alerta antigo na fila (mais de 2 h, ex.: robô ficou pausado)Pergunta ao plantonista antes de abrir: abrir, já aberto à mão (não abre e não avisa o Teams) ou decidir depois (pergunta de novo em 30 min). Sem resposta, o alerta espera e os novos seguem
Alerta com texto ilegível (anexo lido errado pelo fluxo)Não abre chamado: vai para /erro e o Teams avisa para abrir à mão pelo e-mail original
Janela do Edge do robô fechadaNão é erro: o robô avisa e reabre a janela no próximo ciclo
Máquina caiu com um alerta reservadoNa própria máquina, retoma quando o robô volta. Se for outra máquina, o alerta vai para /erro depois de 60 min
Dois robôs ativos ao mesmo tempoCada máquina grava o status em /status, e os dois robôs avisam o plantonista
Robô fecha por erroO vigia (tarefa agendada, a cada 5 min) reabre. Se o plantonista fechou pelo menu, não reabre
Atualização com o robô rodandoO instalador pede para o robô sair, espera o alerta em andamento terminar e abre o robô de novo depois
Contratos

Formato dos arquivos

Entrada · /pendentes

{
  "versao": 2,
  "id": "CHG0047305",  // GMUD: a CHG; Backup: Message-Id do e-mail
  "tipo": "INFRA",  // INFRA, DBA, SO ou BACKUP
  "grupo_executor": "SN_TI_CHG_EXECUTOR_CIRION_INFRA",
  "chg": "CHG0047305",
  "ctask": "CTASK0051234",
  "data_execucao": "29/04/2026 09:30",
  "tipo_mudanca": "Normal",
  "titulo": "Criação de Regras de Segurança",
  "descricao": "Criação de novas regras de segurança nos firewalls...",
  "recebido_em": "2026-04-28T14:02:00-03:00",
  "dados_brutos": "texto tratado do e-mail"
}

O id impede chamado duplicado: numa GMUD, é o número da CHG. Os campos chg, data_execucao e descricao são obrigatórios na GMUD; se faltarem, o robô não abre e avisa. Um bloco teams, se vier, só é repassado ao retorno; o Retorno escolhe o chat pelo tipo.

Retorno · /retorno

{
  "id": "<Message-Id do e-mail>",
  "tipo": "INFRA",
  "titulo": "Criação de Regras de Segurança",
  "status": "ok",  // ou "erro"
  "numero": "RITM0012345",
  "url": "https://envdatacenter.service-now.com/now/nav/ui/classic/...",  // link de tratamento
  "mensagem": "",
  "maquina": "NB-DISPATCH-01",
  "processado_em": "2026-09-25T18:01:12-03:00",
  "teams": { /* copiado da entrada */ }
}

Com status: "ok", a mensagem leva o número e o link de tratamento (“✅ INFRA CHG…: chamado RITM… aberto. Tratar: …”). Com status: "erro", a mensagem no chat avisa que o chamado precisa ser aberto manualmente e traz a mensagem do erro.

O modelo das GMUDs no config.json

{
  "_GMUD": {  // formulário Hosting do Employee Center (POP 11)
    "url_formulario": "/esc?id=sc_cat_item&sys_id=42761d80873931902beeeb930cbb3593",
    "variaveis": { "conta_busca": "SOCIEDADE DE ENSINO SUPERIOR ESTACIO", "conta_codigo": "3-9R2V6QXWXV",
                   "caller": "OPERACAO YDUQS", "categoria": "Other" },
    "validar": { "chg": "CHG\d{{7}}" },
    "passos": [
      { "campo": "Conta *",      "acao": "referencia", "busca": "{conta_busca}", "valor": "{conta_codigo}" },
      { "campo": "CallerID *",   "acao": "referencia", "valor": "{caller}" },
      { "campo": "Categoria *",  "acao": "escolher",   "valor": "{categoria}" },
      { "campo": "Descrição resumida *", "acao": "preencher",
        "valor": "#GMUD {chg} | {time_titulo} | {data_execucao|dd/MM HH:mm} |" },
      { "campo": "Descrição *",  "acao": "preencher", "valor": "{descricao}" }
    ]
  },
  "INFRA": { "herda": "_GMUD", "variaveis": { "time_titulo": "SOC" } },
  "DBA":   { "herda": "_GMUD", "variaveis": { "time_titulo": "DBA" } },
  "SO":    { "herda": "_GMUD", "variaveis": { "time_titulo": "SO" } },
  "BACKUP": { /* mesmos campos, título #FALHA DE BACKUP */ }
}
// fora de "tipos": "envio_automatico": { "GMUD": true, "BACKUP": true } (menu do ícone: Enviar GMUD / Backup sem conferir)

Cada passo tem o nome do campo na tela; o seletor de cada um sai do mapeamento. {campo} vem do alerta, variaveis são valores fixos do tipo e herda reaproveita o modelo. Enquanto houver PREENCHER, o tipo não abre chamado (é o caso de PRODUCAO, que ficou fora do escopo).
